# 开发历史与旧实现审计

这是一份维护者文档，不是项目首页。它说明公开版为何没有直接打包历史 JUCE 目录，以及哪些正确性、实时性和许可问题促成了重写。

## 检查到的历史资产

- JUCE 工程约 1.19 GB，但绝大部分是 `Builds`、`.vs`、OBJ、PDB 和缓存；实际源文件约 160 KB。
- 研究资料约 2.58 GB，其中 DKMethod 目录约 2.28 GB，同样以构建缓存和重复副本为主。
- JUCE `.jucer` 的模块路径已经失效；最近生成的 Visual Studio 工程又硬编码到另一处 JUCE 8.0.8 路径。
- 插件元数据仍是占位的 `yourcompany`，版本状态保存为空。
- MATLAB 完整模型、离线 C++、JUCE 版之间存在多份近似副本；JUCE 版已经包含一部分晚期修复。

因此本仓库只迁移知识和元件拓扑，不迁移旧构建目录、论文 PDF、二进制、训练数据或来源不清的数值代码。

## 正确性问题

| 旧问题 | 影响 | 当前处理 |
| --- | --- | --- |
| `new[]` 后用 `delete` | 未定义行为 | 不再使用手工数组堆分配 |
| Dry/Wet 仅把湿信号乘比例 | 0% Mix 变成静音 | 上采样域真正线性混合 |
| 只处理左声道再复制 | 立体声被折叠 | 每声道独立电路实例 |
| 三极管板极导数用 `Cg` 代替 `Cp` | Newton 雅可比错误 | 修正并以有限差分测试 |
| 板极电流为 `Ik-Ig`，雅可比漏掉 `-dIg` | 残差与导数不一致 | 补全链式导数 |
| 只看电压步长 0.05 V | 可能“步长小但残差大” | 同时检查残差与步长 |
| 无 NaN/不收敛后备 | 状态可永久污染 | 阻尼、有限值保护、失败统计和重置 |
| Bright 两条路径只更新选中者 | 切换后使用陈旧状态 | 两条路径同步推进 |

## 实时音频问题

| 旧问题 | 当前处理 |
| --- | --- |
| 每块 `malloc/free` | `prepareToPlay` 预分配，逐样本固定尺寸对象 |
| 块长改变时音频线程 `new/delete` | 按宿主最大块长准备，超长块安全清零 |
| 每次 Newton 做 Jacobi SVD 伪逆 | 直接求解 4×4 线性系统 |
| 旋钮字段由 UI 普通写、音频线程普通读 | APVTS 原子参数 |
| `prepareToPlay` 为空、固定从 44.1 kHz 构造 | 按实际采样率及 4× 因子准备 |
| 没有宿主参数与状态恢复 | 完整 APVTS 参数布局和 XML 状态 |
| 无抗混叠策略 | 4× 上/降采样包围非线性电路 |

## 许可问题

旧资料中可见的 DKMethod JUCE 模块带 GPLv3；另一个 NodalDKFramework 目录同时出现非商业声明和 GPL 文件；Jacobi SVD 副本未找到清晰许可。把这些源文件原样发布并再声明宽松许可是不安全的。

本仓库采取以下边界：

- 固定尺寸矩阵和求解器为重新实现，不带入旧 SVD 源码；
- 电路元件值、公开论文方程和项目自己的研究结论以文档归因；
- 不分发论文、书籍、官方原理图扫描和旧二进制；
- 仓库原创代码统一使用 AGPL-3.0-or-later，与 JUCE 8 的开源使用方式保持清晰边界。

这不是法律意见；若计划闭源或商业分发，仍需审查 JUCE、插件 SDK、商标和所用测量素材的许可。

## 仍保留的模型限制

- 第一只三极管只是局部线性拟合，不会产生真实的栅流、截止和压缩。
- 模块拆分忽略了部分级间双向负载耦合。
- Tone Stack 的 Bass 控制沿用线性参数映射，未模拟实机对数电位器规律。
- 参数跳变未做完整电路级平滑；音调矩阵重建可能造成瞬态。
- 4× 过采样降低但不能证明消除了全部混叠。
- 没有组件容差、老化、噪声、微音效应、功放、变压器、扬声器和麦克风模型。
